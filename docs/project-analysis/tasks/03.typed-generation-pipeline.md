## Objetivo

Eliminar a fronteira interna baseada em arrays de argumentos. A CLI continuará aceitando texto, mas traduzirá seus argumentos para requests tipados. WPF, Avalonia, exportação e gravação usarão os mesmos requests, validação e `GenerationPlan`.

## Contratos esperados

```csharp
public abstract record GenerateDiscRequest;
public sealed record GenerateCdRequest(...) : GenerateDiscRequest;
public sealed record GenerateDvdRequest(...) : GenerateDiscRequest;
public sealed record GenerateBluRayRequest(...) : GenerateDiscRequest;

public interface IDiscGenerationService
{
    Task<GenerationPlan> PlanAsync(GenerateDiscRequest request, CancellationToken token);
    Task GenerateFileAsync(GenerationPlan plan, string outputPath,
        IProgress<GenerationProgress>? progress, CancellationToken token);
    Task GenerateStreamAsync(GenerationPlan plan, Stream output,
        IProgress<GenerationProgress>? progress, CancellationToken token);
}
```

Os nomes são ilustrativos; o importante é separar request, validação, planejamento e destino.

## Escopo

- Requests imutáveis e específicos por mídia.
- Resultado de validação com código, campo e parâmetros localizáveis.
- Plano contendo geometria efetiva, filesystem, ranges, tamanho estimado, sidecars e capacidades exigidas.
- Destinos file/stream consumindo o mesmo plano.
- Adapter CLI responsável por parsing e help.
- Builders da WPF migrados para usar os requests, reduzindo risco antes do port visual.

## Plano de implementação

1. Catalogar todas as opções atualmente montadas por `ExportViewModel`, `BurnViewModel` e CLI.
2. Definir requests sem strings de linha de comando e sem tipos de UI.
3. Centralizar defaults e invariantes hoje duplicados.
4. Adaptar cada módulo CD/DVD/BD para produzir um plano normalizado.
5. Implementar destinos para arquivo e stream.
6. Alterar a CLI para converter parser → request e preservar mensagens/exit codes.
7. Alterar WPF Export/Burn gradualmente e comparar artefatos.
8. Expor resumo legível do plano para a GUI Avalonia.

## Critérios de aceite

- Nenhum ViewModel novo monta flags como `--r0`, `--tone-dither` ou `--file-position`.
- CLI e API tipada geram artefatos byte a byte idênticos para vetores pequenos.
- Exportação e streaming usam o mesmo plano e reportam o mesmo filesystem/range/tamanho.
- Defaults do descritor, parser e request não divergem.
- Erros possuem códigos estáveis, sem a UI analisar `Exception.Message`.
- Cancelamento alcança planners e loops de escrita.

## Testes obrigatórios

- Golden vectors para CD áudio/dados, DVD e BD drawing-only/com UDF.
- Comparação file versus stream.
- Parsing CLI versus construção direta do request.
- Rejeição de geometria, paths, capacidade e combinações inválidas.
- Progresso monotônico e cancelamento em planejamento e escrita.
- Help e resumo coerentes com ISO9660/Joliet, CD-DA ou UDF 2.01 reais.

## Migração

Manter `IOpticalDiscModule` como fronteira pública. O adapter de módulo pode construir request tipado internamente. Remover o caminho textual da GUI somente depois que os vetores provarem equivalência.

## Implementação entregue

- Biblioteca portátil `DiscImageStudio.Generation`, sem dependência de UI ou sistema operacional.
- Requests imutáveis e específicos para CD, DVD e Blu-ray, incluindo byte order, filesystem, posição de arquivos, tom e inversão como valores tipados.
- `GenerationPlan` com filesystem real, faixa de desenho, tamanho, arquivos, sidecars, capabilities e detalhes físicos por mídia.
- `DiscGenerationService` compartilhando o mesmo plano e produtor sequencial entre arquivo, stream e gravação.
- Validação estruturada por código, campo e parâmetros, sem exigir parsing de mensagens pela UI.
- Adapter `TypedGenerationCommandLine`; os comandos de geração da CLI convertem texto somente na borda.
- Exportação WPF e gravação WPF migradas para `GenerationRequestFactory` e `IDiscGenerationService`, eliminando a reconstrução de flags nesses fluxos.
- Resumo do plano exposto para hosts e futura interface Avalonia.
- Cinco golden vectors SHA-256 e testes de equivalência file/stream, CLI/API, layouts, validação, progresso e cancelamento.
- Guia de contratos, ownership e threading em [GENERATION_PIPELINE.md](../../GENERATION_PIPELINE.md).

A prévia/readback mantém temporariamente a fronteira pública `IOpticalDiscModule`; sua API visual tipada e consumo do plano serão concluídos na Task 10, sem voltar a acoplar geração à sintaxe da CLI.

## Fora de escopo

- Layout Avalonia.
- Política final de publicação atômica, detalhada na Task 11.
- Implementação do dispositivo Linux.

## Riscos

- Diferenças ocultas de byte order entre arquivo e IMAPI devem virar opções explícitas do destino, não defaults implícitos.
- Um `GenerationPlan` universal não deve apagar diferenças físicas; usar composição comum e detalhes tipados por mídia.
