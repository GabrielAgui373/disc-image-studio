## Objetivo

Estabelecer uma base verificável antes do port das telas. O projeto Avalonia deve compilar isoladamente no Fedora, e regras automatizadas devem impedir que a nova GUI recupere acidentalmente dependências de WPF, COM, IMAPI ou APIs Windows-only.

## Contexto

O scaffold atual compila em `net10.0`, mas ainda não referencia as camadas do produto. A solução completa contém projetos `net10.0-windows`, portanto `dotnet build DiscImageStudio.slnx` não é um comando Linux válido sem separar o conjunto de projetos.

## Escopo

- Criar uma solução/filtro Linux contendo Avalonia, CLI, Core, ImageIO portátil, ISO, CD, DVD, Blu-ray e testes portáveis.
- Alinhar o `.csproj` Avalonia com `Nullable`, `ImplicitUsings`, warnings como erros e metadados do produto.
- Fixar uma política única para versões Avalonia e CommunityToolkit, preferencialmente via gerenciamento central de pacotes se o repositório aceitar essa mudança.
- Criar testes de arquitetura que inspecionem referências de projeto e assemblies.
- Documentar comandos de restore, build, test e run no Fedora.
- Registrar uma matriz inicial de paridade entre telas WPF e entregas Avalonia.

## Regras a automatizar

1. `DiscImageStudio.App.Avalonia` pode depender de `DiscImageStudio.Application`, projetos portáveis e Avalonia.
2. A GUI Linux não pode referenciar `DiscImageStudio.App`, `DiscImageStudio.Imaging`, `DiscImageStudio.Burning` Windows, `PresentationCore`, `PresentationFramework` ou `System.Windows`.
3. Projetos de domínio/aplicação não podem referenciar Avalonia.
4. Código sob `net10.0` não pode usar APIs anotadas como Windows-only sem adapter condicionado.
5. O conjunto Linux precisa restaurar e compilar sem `EnableWindowsTargeting`.

## Plano de implementação

1. Inventariar targets e referências reais com `dotnet list reference` e assets de restore.
2. Criar `DiscImageStudio.Linux.slnx` ou solução equivalente explícita.
3. Adicionar propriedades de qualidade ao projeto Avalonia.
4. Criar teste de arquitetura portátil; não reutilizar o harness Windows como única proteção.
5. Adicionar job Fedora/Ubuntu ao CI para restore, build Release e testes portáveis.
6. Salvar tempo, SDK, RID e warnings como artefato textual do job.
7. Atualizar `VALIDATION.md` somente após uma execução real.

## Critérios de aceite

- `dotnet build <solução-linux> -c Release` passa no Fedora com zero warnings.
- O projeto Avalonia aparece no conjunto Linux e os projetos WPF/IMAPI não aparecem.
- Um teste proposital que adicione referência a WPF/Avalonia na camada errada falha com mensagem clara.
- O SDK usado satisfaz `global.json` e é registrado no log do CI.
- O README informa comandos exatos e bibliotecas nativas necessárias.
- A matriz de paridade identifica ao menos Home, Projeto, Design, Prévia, Exportação, Gravação, Calibração, Configurações e Sobre.

## Testes e evidências

- Build Debug e Release do Avalonia.
- `dotnet test` do projeto de arquitetura portátil.
- Publicação framework-dependent `linux-x64` como smoke inicial.
- Inspeção do `.deps.json` para confirmar ausência de WPF/WindowsDesktop.

## Implementação entregue

- `DiscImageStudio.Linux.slnx` com os projetos portáveis e a GUI Avalonia.
- `DiscImageStudio.PortableArchitectureTests` com dez testes descobríveis por `dotnet test`.
- Job `linux-gui` no workflow de build para restore, build, testes e publish `linux-x64`.
- Metadados, warnings como erros, compiled bindings e versão Avalonia única no projeto da GUI.
- Hello World executável como smoke visual.
- Guia [Desenvolvimento da GUI Linux/Avalonia](../../LINUX_GUI_DEVELOPMENT.md), incluindo pré-requisitos, comandos e matriz de paridade.
- Validação local registrada em [VALIDATION.md](../../VALIDATION.md).

## Fora de escopo

- Implementar telas funcionais.
- Portar composição visual.
- Fazer a solução Windows compilar nativamente no Linux.
- Escolher o backend de gravação Linux.

## Riscos

- Centralizar versões de todos os pacotes pode ampliar o diff; limitar a mudança aos projetos envolvidos se necessário.
- Um filtro de solução não substitui testes de arquitetura, pois referências proibidas ainda poderiam ser adicionadas diretamente.
