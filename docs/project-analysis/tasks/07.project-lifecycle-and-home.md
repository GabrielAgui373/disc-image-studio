## Objetivo

Entregar o fluxo completo de projeto antes do editor visual: Home, templates, novo projeto, recentes, abrir/salvar/salvar como, dirty state, configurações do projeto e recuperação de assets ausentes.

## Escopo funcional

- Home com ações primárias, templates por mídia e projetos recentes.
- Diálogo de novo projeto com família imutável, preset, nome, pasta e parâmetros avançados progressivos.
- Abrir `.discproj` existente criado na WPF.
- Salvar, salvar como, fechar e sair com alterações pendentes.
- Configurações do projeto e presets do usuário.
- Remoção/limpeza de recentes inválidos sem apagar projetos.
- Resolução de paths relativos e absolutos.
- Fluxo de relink para imagens ausentes.
- Comando “coletar projeto” opcional em sub-PR, copiando assets para pasta controlada.

## Regras de portabilidade

1. Asset abaixo da pasta do projeto deve ser salvo como path relativo quando isso não quebrar compatibilidade.
2. Paths absolutos legados continuam aceitos.
3. Relink deve permitir uma substituição individual e busca em pasta, sem alterar silenciosamente arquivos incorretos.
4. Tamanho/hash opcionais podem detectar substituição silenciosa; qualquer mudança de schema exige versão e migração.
5. Nunca copiar, mover ou apagar asset do usuário sem ação explícita.

## Plano de implementação

1. Portar cards e estados vazios da Home.
2. Conectar templates/presets do Core ao novo diálogo.
3. Implementar lifecycle pelos casos de uso da Task 02.
4. Implementar recentes no diretório XDG, com deduplicação por path normalizado.
5. Implementar dirty prompt consistente para fechar, abrir outro e sair.
6. Implementar painel de assets ausentes e relink.
7. Adicionar thumbnail assíncrono com fallback, sem bloquear a Home.
8. Validar compatibilidade cruzada WPF ↔ Avalonia.

## Critérios de aceite

- Projetos CD/DVD/BD criados na WPF abrem na Avalonia sem alteração do arquivo.
- Projeto salvo na Avalonia reabre na WPF quando usa somente campos conhecidos.
- Cancelar Save As ou fechar prompt não altera dirty state nem paths.
- Recentes com arquivo removido mostram estado claro e podem ser removidos da lista.
- Assets ausentes não impedem acessar configurações e relink.
- Família da mídia não pode ser trocada após criação.
- Erros de permissão, JSON e schema são diferenciados e acionáveis.

## Testes

- Golden files de schemas atual e anterior.
- Paths com espaços, Unicode, symlinks, case differences e diretórios movidos.
- Projeto read-only, destino sem espaço e interrupção durante save.
- Dirty state para mudanças persistentes versus zoom/navegação.
- Recentes corrompidos e thumbnails inválidos/limite de tamanho.
- Compatibilidade round-trip entre hosts.

## Fora de escopo

- Edição visual das camadas.
- Empacotamento ZIP do projeto.
- Sincronização em nuvem.

## Riscos

- Linux é case-sensitive e Windows normalmente não; detectar colisões antes de coletar assets.
- Symlinks podem escapar da pasta coletada; resolver e validar destinos antes da cópia.
