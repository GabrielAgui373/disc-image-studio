## Objetivo

Fechar a implementação com uma matriz explícita de paridade e limitações. O release Linux não precisa copiar toda capacidade Windows no primeiro dia, mas deve declarar com precisão o que funciona, o que é experimental e o que permanece indisponível.

## Matriz de paridade

Para cada fluxo, registrar `Completo`, `Parcial`, `Experimental` ou `Indisponível`:

- Home, novo/abrir/salvar projeto e recentes;
- Design, camadas, tom, filesystem e undo/redo;
- Preview projetado e readback CD/DVD/BD;
- Exportação por formato e validação;
- Calibração por mídia;
- Gravação por mídia/modo/dispositivo;
- Settings, tema, idioma, About e diagnóstico;
- compatibilidade `.discproj` WPF ↔ Avalonia.

Cada status precisa de evidência, issue conhecida e comportamento da UI. Recursos indisponíveis ficam escondidos ou desabilitados com motivo acionável, nunca falham somente após iniciar um job longo.

## Jornadas end-to-end

1. Criar projeto CD, compor, salvar, exportar e validar/readback.
2. Abrir projeto DVD da WPF, relinkar asset, editar, undo/redo e exportar.
3. Criar projeto BD com arquivos, confirmar UDF 2.01, exportar e gerar sidecar.
4. Gerar alvo, salvar sessão, reabrir, calibrar e aplicar preset.
5. Cancelar exportação em diferentes estágios e confirmar integridade.
6. Executar capability flow de gravação com ausência de device/permissão e, quando suportado, hardware real.
7. Trocar tema/idioma e reiniciar preservando settings/projeto.
8. Instalar, atualizar e remover pacote em Fedora limpo.

## Processo de beta

- Publicar prerelease separado do canal Windows estável.
- Fornecer template de issue com versão, Fedora, sessão gráfica, GPU, mídia/device e pacote de diagnóstico.
- Recrutar cenários com diferentes DPI, drivers, X11/XWayland e hardware óptico.
- Classificar bugs por perda de dados, saída incorreta, crash, acessibilidade e visual.
- Definir janela de estabilização sem features antes do release estável.

## Critérios de go/no-go

### Bloqueadores

- corrupção/perda de projeto ou sobrescrita não confirmada;
- artefato final publicado após cancelamento/falha;
- divergência não explicada entre CLI e GUI para o mesmo plano;
- crash recorrente no fluxo principal;
- capability de gravação habilitada sem validação correspondente;
- incompatibilidade de schema sem migração/aviso;
- violação das fronteiras WPF/Windows no pacote Linux.

### Requisitos para release

- build/test/publish verdes e reproduzíveis;
- jornadas P0 aprovadas em Fedora suportado;
- docs de instalação, limitações, troubleshooting e recuperação;
- checksums, licenças, SBOM e notas de release;
- pacote de diagnóstico revisado quanto à privacidade;
- plano de rollback e preservação de configurações/projetos.

## Entregáveis

- matriz de paridade versionada;
- relatório de validação com commit, SDK, pacote e ambiente;
- lista de limitações conhecidas;
- screenshots atuais das telas Linux;
- changelog e guia de migração;
- matriz física para qualquer gravação habilitada;
- decisão explícita sobre estabilidade do backend Linux.

## Fora de escopo

- Declarar paridade de gravação sem evidência física.
- Remover a WPF ou forçar migração dos usuários Windows.
- Ampliar suporte para outras distribuições durante estabilização do Fedora.

## Resultado esperado

Ao concluir o escopo aprovado, o Disc Image Studio terá uma GUI Linux que reutiliza os motores portáveis sem duplicar regras, oferece uma experiência de projeto comparável à WPF, melhora integridade/diagnóstico e comunica honestamente as limitações de hardware.
